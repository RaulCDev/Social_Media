# Scorecard

1. Good design is innovative — Score: 1/3
   Evidence: Standard OAuth button and profile anchors (`01-evidence.md`, Structural).
   Justification: It executes a familiar pattern cleanly rather than introducing a new one.
2. Good design makes a product useful — Score: 3/3
   Evidence: The primary task starts in one click (`01-evidence.md`, Structural).
   Justification: No detour stands between the visitor and GitHub authentication.
3. Good design is aesthetic — Score: 2/3
   Evidence: Coherent 72/24/18 hierarchy, with a mobile contrast edge case (`01-evidence.md`, Visual).
   Justification: The system is visually disciplined, but the responsive CTA label needs one small accessibility refinement.
4. Good design makes a product understandable — Score: 2/3
   Evidence: `Continue with GitHub` names the provider but not the sign-in action (`01-evidence.md`, Copy and honesty).
   Justification: One label can be made more explicit without structural change.
5. Good design is unobtrusive — Score: 3/3
   Evidence: Only the title, primary action, and quiet secondary links are visible (`01-evidence.md`, Structural).
   Justification: The interface recedes and lets the single task dominate.
6. Good design is honest — Score: 2/3
   Evidence: No inflated claims, but first-use profile creation is not disclosed (`01-evidence.md`, Copy and honesty).
   Justification: There is a minor transparency gap, not a deceptive flow.
7. Good design is long-lasting — Score: 3/3
   Evidence: Solid colors, system typography, simple geometry, and no ornamental trend effects (`01-evidence.md`, Visual).
   Justification: The visual language is restrained enough to age well.
8. Good design is thorough down to the last detail — Score: 2/3
   Evidence: Interaction states exist, while OAuth failures use one generic message (`01-evidence.md`, Visual; Copy and honesty).
   Justification: One recovery state remains rough.
9. Good design is environmentally friendly — Score: 2/3
   Evidence: 146kB first-load JS, no idle motion or media (`01-evidence.md`, Weight and friction).
   Justification: It is light in attention and media, though not under the 100kB top threshold.
10. Good design is as little design as possible — Score: 2/3
    Evidence: The two profile links are the only elements not required for authentication (`01-evidence.md`, Structural).
    Justification: The screen is highly restrained, with at most two removable secondary actions.

**Total: 22/30**
